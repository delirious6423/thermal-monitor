# Building and publishing a release

The initial binary target is Linux x86-64, statically linked to musl. It does not
need a system glibc version or a Rust installation on the user's computer. D-Bus,
a tray host and systemd user services are still required; Python 3.10+ is used
by the installer. Other architectures are rejected rather than guessing a binary.

## Build prerequisites

Use Rust 1.99+ on an x86-64 GNU/Linux build machine, with its matching official
`x86_64-unknown-linux-musl` standard-library component and bundled `rust-lld`.
Python 3, Git and GNU binutils (`readelf`) are also required. Use the official
Rust standalone component installer and verify its published SHA-256 before
installing it into your chosen toolchain prefix. No runtime packages are bundled
from a developer's home directory.
The matching official `share/doc/rust/COPYRIGHT-library.html` must also be present
in the selected sysroot so the runtime's public attribution can be packaged.
The builder includes license files from the locked dependency graph, including
build/test dependencies, without embedding their local source paths.

The builder honors `RUSTC` for a separate compiler/sysroot and does not install
toolchain components, packages or privileged services. It intentionally replaces
target Rust flags and disables a configured compiler wrapper for the release build.

## Checks and package

Review and commit the source first; the builder refuses a dirty worktree.

```sh
cargo fmt --all --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --locked --all-features
cargo test --locked --doc
cargo deny check
cargo machete
python3 tests/vm/check-desktop.py
python3 -m unittest discover -s tests -p test_release.py
python3 scripts/build-release.py
```

The builder emits exactly these publishable assets under `dist/`:

- `thermal-monitor-linux-x86_64.tar.gz`: executable, installer, project and dependency licenses,
  documentation and optional integration files, with a per-file manifest.
- `install.py`: standalone online/offline installer.
- `PRIVACY-AUDIT.json`: source commit and successful privacy/metadata checks.
- `SHA256SUMS`: hashes for the other three assets.

The archive records `VERSION` and `SOURCE_COMMIT`. It does not contain `.git`,
source build caches, local receipts/backups or telemetry. Checksums are integrity
checks; see [PRIVACY.md](PRIVACY.md) for their trust limits.

## Disposable-VM validation

Use the existing VM harness and `tests/vm/provision.sh` with hostname
`thermal-release-test`, user `tester` (UID 1000). Install `sysstat` in the VM.
Copy the repository to `~/thermal-test` and the four assets to `~/release-test`.
Then run these inside that VM, never on your desktop:

```sh
cd ~/thermal-test
bash tests/vm/setup-release.sh
python3 tests/vm/check-release-install.py
```

The setup creates a VM-only fake NVIDIA command, headless Sway/Waybar and sensor
fixtures. The checks exercise fresh install, actual tray behavior, repeated
install, optional components, edited-file protection, failed-start rollback,
uninstall and retained logs. Keep reports and actual hardware logs local.

## Publish

Match the tag to Cargo's version. Push only the reviewed public branch and tag,
never unrelated local branches containing private history. Create a draft with
explicit asset names; review it before publishing. For version 0.1.0:

```sh
git tag v0.1.0
git push origin main v0.1.0
gh release create v0.1.0 --verify-tag --draft --title 'Thermal Monitor 0.1.0' \
  --notes-file /path/to/reviewed-release-notes.md \
  dist/thermal-monitor-linux-x86_64.tar.gz dist/install.py \
  dist/PRIVACY-AUDIT.json dist/SHA256SUMS
gh release edit v0.1.0 --draft=false
```

After publishing, verify all assets against `SHA256SUMS` and test the online
installer anonymously in the disposable VM. Source archives automatically
generated by GitHub are not the prebuilt binary package.
